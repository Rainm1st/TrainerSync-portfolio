Project Overview

Project Architecture

TrainerSync: session queue → voice-first live training (screen fallback) → map + buddies. Plan, execute, recap—lightweight, not a chat app.

Why this architecture matters

Library + live cues + floor social + coach view in one flow.

1. Motivation & Research

The Why

Authorship (CPT208): motivation through evaluation is Team C3-6. Gen-AI only for captioned visuals. Build: vibe coding. We checked fit to the brief and non-clinical wording on vitals/coaching.

Gyms need live coordination, not only pre/post logs. TrainerSync links trainee and coach with status cues, light telemetry, and in-session feedback—plus playful touches that motivate without replacing safety. Active Lifestyles let us combine IA, flows, and fitness content in one product story.

The Gap: Academic Papers

Source 3 Things Done Well 3 Things Missed
Angosto et al. (2023)
  • Provides an up-to-date synthesis of fitness-app adoption studies between 2020 and 2023.
  • Compares multiple acceptance models (including TAM and UTAUT variants) in one review frame.
  • Highlights hedonic motivation and gamification as practical satisfaction drivers.
  • Focuses on intention-to-use surveys more than real gym-floor behaviour.
  • Does not specify actionable coach-dashboard interaction patterns.
  • Provides limited guidance on spatial equipment discovery in busy gym contexts.
Mazeas et al. (2022)
  • Uses rigorous RCT-based meta-analysis rather than anecdotal app reports.
  • Shows that gamification can improve physical activity outcomes versus inactive controls.
  • Reports post-intervention durability instead of only short-term novelty effects.
  • Aggregates highly heterogeneous app designs, reducing direct design transferability.
  • Offers little detail on coach-facing supervision workflows.
  • Does not address multi-user coordination and messaging during live sessions.
Mair et al. (2023)
  • Provides an umbrella-level synthesis across many digital health intervention reviews.
  • Links concrete behaviour-change techniques to evidence (feedback, goals, social support).
  • Helps justify structured motivational features in a human-centred system.
  • NCD prevention framing dominates, while gym-specific use is secondary.
  • Gives limited UI-level guidance for trainee-coach interfaces.
  • Under-specifies playful micro-interactions at high-exertion moments.
Nishi et al. (2024)
  • Offers large pooled evidence on digital health app effectiveness.
  • Shows stronger effects when gamification elements are present.
  • Connects app usage to activity and cardiometabolic risk-related outcomes.
  • Primarily outcome-focused rather than interaction-design-focused.
  • Does not prescribe UX patterns for trainee-coach binding and monitoring.
  • Provides limited ethical interface guidance for real-time physiological displays.

The Gap: Commercial Products

Keep
  • Large and practical exercise library for mainstream fitness scenarios.
  • Accessible training plans that support beginners with clear structure.
  • Mobile-first interaction flow that is easy to start and follow.
  • Weak live linkage between trainee and professional coach.
  • Limited adaptation for on-site gym supervision needs.
  • Feedback is mostly individual and post-hoc rather than in-session.
Apple Fitness+
  • High production quality in video and guided class experience.
  • Strong ecosystem integration with Apple devices and wearables.
  • Clear guided workout flow for individual follow-along sessions.
  • No dedicated coach dashboard for remote monitoring tasks.
  • Not designed for gym-floor multi-person supervision.
  • Weak support for coordinating multiple trainees in parallel.
Strava
  • Strong activity tracking and long-term performance records.
  • Mature social visibility and community interaction features.
  • Useful trend history for progress reflection over time.
  • Not instruction-centred for movement coaching.
  • Limited support for indoor equipment-focused gym workflows.
  • No integrated live correction pipeline between coach and trainee.
Nike Training Club
  • Well-structured workout plans with clear session organization.
  • Polished coaching content and high usability for guided training.
  • Approachable across beginner to advanced ability levels.
  • No real-time intervention channel for professional coaches.
  • Limited adaptive support for group or multi-trainee supervision.
  • Session recap is not centred on coach decision and follow-up logic.

Current Functional Requirements

FRs = must-do behaviour. PHs below = tone only.

FR1 · Session queue, live execution, and post-training recap

Objective: Pre: category multi-select → in-session queue. During: demos, short calibration copy, substitutes, next-step nudges from the queue (scripted, non-clinical). Post: recap + trends (e.g. HR chart—mock OK for demo).

Expand behaviours & acceptance checks

Behaviours & data rules

  • Pre-session: Category selections accumulate into a visible queue; users reorder or drop items before starting; inputs may combine with equipment, duration, and level constraints depending on generator depth in the build.
  • In-session: Active movement shows demo media plus concise calibration copy; queue progress shows what is current versus upcoming.
  • Continuity: “Next movement” suggestions reference the queued plan or an approved substitute path—never ad-hoc medical judgement.
  • Post-session: Recap ties outcomes back to the executed queue; HR visualisation reads as a time-series suitable for reflection (exact sensor integration optional).
  • Empty or blocked generator states explain which constraint failed and propose relaxations.

Acceptance checks

  • Walkthrough: pick categories → confirm queue → start session → complete block → open recap without losing traceability between screens.
  • Observers locate demo, calibration cues, and queue/next-step affordances within two scroll lengths on mobile breakpoints.
  • Keyboard and screen-reader order follows generator → queue → live execution → recap.

FR2 · Real-time guidance: voice-led (Plan A) with screen fallback (Plan B)

Objective: Plan A — Voice: tempo, breath, coach/threshold lines, light tones (non-diagnostic). Plan B — Screen: HR “breathing” visual, message stream, emoji/chips—same intent if voice fails. Captions mirror voice.

Expand behaviours & acceptance checks

Behaviours & data rules

  • Plan A: Predictable cue beats (cadence, breath, rest countdown, set transitions); mocked telemetry allowed with shared disclaimers.
  • Plan B: HR communicated via prominent rhythmic visual treatment; messages readable at arm’s length; emoji/interactions require ≤2 taps.
  • Either path exposes pause, skip cue, and end-session without trapping the user.
  • The portfolio build documents which plan is primary in the hosted prototype while stating parity intent for coursework reviewers.

Acceptance checks

  • Primary-path walkthrough (voice if enabled): scripted three-set block completable with audio-led tempo, breath, timer, and completion acknowledgement.
  • Fallback-path walkthrough: voice muted → user completes the same script using on-screen messaging + HR visual within +20% time.
  • prefers-reduced-motion keeps timers and essential readouts while toning ornamental pulses.

FR3 · Gym-floor map, occupancy-aware flow, and equitable buddies

Objective: Map: equipment + occupancy (e.g. 4/5—sim data OK). Text strip under map. Next-step hints = FR1 queue + rules (no black-box “AI”). Buddies: region filters, fair cards, HELP / HOW / HI + short emoji messages.

Expand behaviours & acceptance checks

Behaviours & data rules

  • Map pins or zones expose equipment category plus occupancy ratio; legend clarifies what the numerator/denominator mean for reviewers.
  • Copy strip updates when filters change; it never impersonates live gym CCTV—only reflects prototype data contracts.
  • Next-move recommendations cite queue position + occupancy outcome (“planned bench busy → approved swap”) rather than opaque “AI magic.”
  • Buddy discovery respects consent toggles; HELP/HOW/HI lanes keep tone distinct so urgency reads correctly.
  • Optional coach routing remains opt-in with revoke-clear behaviour as before.

Acceptance checks

  • Scenario: trainee sees target station congested, reads digest, accepts a substitute or alternate zone without abandoning the timer surface.
  • Buddy filter produces cards without exposing graded skill labels reviewers could misread as discriminatory metadata.
  • Moderation-ready logging (mocked) tags HELP vs HOW vs HI separately.

Playful Must-Haves

PH1–PH3: feel of FR1–FR3—human, light delight; never trade safety for gamification.

PH1 · Delight in “today’s stack”

Design intent (↔ FR1): Queue feels like a plan, not a spreadsheet—motion + type support choices; cues stay readable.

Expand acceptance criteria & mapped screens

Acceptance criteria:

  • Queue reveal ≤400ms (or static); generator stays visible.
  • Stack state = colour + icon + text (colour-blind safe).
  • No shame copy; autonomy-first tone.

PH2 · Voice character & presence

Design intent (↔ FR2): Calm coach-like voice; screen fallback as clear; short chimes/emoji, no noise overload.

Expand acceptance criteria & mapped screens

Acceptance criteria:

  • Voice preview before session; persona swap keeps timers aligned.
  • Affirmations <3s; never over talk safety/breath.
  • Muted = same supportive text tone.

PH3 · Trusted floor companionship

Design intent (↔ FR3): Map scannable; buddies fair + opt-in; HELP/HOW/HI stay kind, not surveillance.

Expand acceptance criteria & mapped screens

Acceptance criteria:

  • Help copy kind + snoozeable.
  • Reactions ≤2 taps; no full chat unless opted in.
  • Coach surfaces show availability + thanks.

3. Ideation & Alternatives

Design Alternatives and Low-Fi Prototype

Alternative A: AR Pose Estimation

High novelty and potentially rich correction, but intrusive in a gym setting and dependent on camera framing, lighting, and privacy consent.

Alternative B: Session queue + dual-channel guidance + map-first gym connect

Chosen: queue + recap, voice/screen live layer, map + occupancy + fair buddies (HELP/HOW/HI)—less waiting, no heavy chat.

Alternative C: Summary-Only Tracker

Useful for records, but too passive because it only explains performance after the moment when support was needed.

Pick: B fits the floor—coach attention, trainee clarity, no camera stack.

Crazy Eights

Eight quick sketches per person (~8 min), after pain points, before locking B—rough on purpose.

Prompts: floor findability, in-set encouragement, coach scan load, safe social signals. Cluster → wireframe.

You are helping with a CPT208 static fitness web prototype called TrainerSync hosted on GitHub Pages. Stack: plain HTML/CSS/JS or minimal tooling only. Do NOT invent new product requirements.

Prompt A — shell & routing:
“Here is our screen list: Home, Exercise Library, Exercise Detail, Live Training, Map, Companion, Profile, Coach Dashboard, Trainee List, Live Detail, Messages. Create a shared nav/header pattern and separate HTML pages OR hash routes so each URL works when refreshed on GitHub Pages. Use relative paths only.”
Prompt B — Live Training panel:
“Implement the Live Training page from this wireframe snippet [paste]. Use mock data for heart rate (updates every 2s within 110–165 bpm). Show set counter and a non-medical disclaimer line we provide verbatim: ‘For wellness motivation only—not medical advice.’ Colours must match tokens #c8f542 accent and dark navy background.”
Prompt C — coach dashboard grid:
“Coach Dashboard needs responsive CSS grid: 2 columns on desktop, 1 column <768px. Cards show trainee name, status pill, sparkline placeholder. Fix overflow-x without horizontal scroll on mobile.”
Prompt D — map / companion stubs:
“Map page: embed a lightweight mock map container (static image or CSS grid) with clickable pins that open a small emoji reaction tray (fire, muscle, thumbs-up). No real geolocation API required—use fake coordinates.”
Prompt E — accessibility pass:
“Audit focus order for the Live Training controls (pause, end session). Add visible :focus outlines matching brand lime; ensure buttons have aria-labels where icons are textless.”
Prompt F — deployment bug:
“GitHub Pages returns 404 for nested routes /coach/live. Refactor to hash routing (#/coach/live) OR relative paths; show exact diff.”
Prompt G — playful UI polish:
“Add subtle CSS pulse on the heart-rate ring when crossing mock ‘amber’ threshold; keep reduced-motion fallback via prefers-reduced-motion.”
